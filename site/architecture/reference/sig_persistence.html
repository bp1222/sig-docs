sig_persistence_key_fn

typedef sig_status_t (*sig_persistence_key_fn)(const char *key, void *ctx);

Called once per key by `list`. `key` is valid only for the duration of the callback; copy it to keep it. A status other than SIG_OK stops the listing and is returned from it.

sig_persistence_module

typedef struct {
    const char *name;
    sig_status_t (*create)(const char *config, void **out_state);
    void (*destroy)(void *state);
    sig_status_t (*load)(void *state, const char *ns, const char *key, void **out_data, size_t *out_len);
    sig_status_t (*save)(void *state, const char *ns, const char *key, const void *data, size_t len);
    sig_status_t (*remove)(void *state, const char *ns, const char *key);
    sig_status_t (*list)(void *state, const char *ns, sig_persistence_key_fn fn, void *ctx);
} sig_persistence_module;

A persistence module (backend) stores opaque blobs under a (namespace, key) pair. What a namespace means is up to the backend (the file backend maps it to a directory), and so is which names it accepts: a backend returns SIG_ERR_INVALID_ARG for a namespace or key it cannot store. `name` and `create` are required. A NULL data hook makes the matching sig_persistence_* call return SIG_ERR_INVALID_ARG. Hooks block; they are meant for configuration I/O, not the event loop's hot path. - load: *out_data is allocated with sig_alloc and owned by the caller. A missing key (or namespace) is SIG_ERR_NOT_FOUND. - save: creates or replaces the key; data is borrowed. - remove: a missing key (or namespace) is SIG_ERR_NOT_FOUND. - list: calls fn once per key stored in ns; a namespace that holds nothing (or does not exist) lists zero keys. The order is backend-defined (the file backend sorts). fn must not save or remove keys in the namespace being listed.
