libsig

A lightweight IoT platform.
Get startedRead the docs

libsig is the code. The product it is meant to become is a lightweight IoT platform. The aim is that you build libsig onto your devices and run cloud instances that process the signal data. The unit a system is assembled from is the capsule, a piece of code that is meant to run on a device or in the cloud. Today capsules run in the host, a program that runs on POSIX systems (Linux and macOS). See the Roadmap for what is planned and not built.

Capsules

Units of logic. A capsule has named input and output terminals and a table of the properties it accepts. Built-in capsules include a counter, a simulator, a logger, a filter, a switch and a state-change detector.

Services

Wire capsules together. A service connects output terminals to input terminals and runs its capsules on one worker thread.

Host + API + UI

Manage it live. The host, sighost, loads a JSON project and runs it. A management API (C and REST), a WebSocket signal feed and a web UI let you inspect, control and edit a running project.

A project is a directory of JSON files. Each capsule configuration names a capsule and its properties; each service lists configurations as instances and connects their terminals. The management API and the web UI edit those same files.

Roadmap

Section titled “Roadmap”

These items are planned. None of them is built. Nothing above this heading depends on them.

  • Microcontroller targets (planned): running capsules on a microcontroller, for example an Arduino reading a GPIO pin. libsig supports POSIX only today.
  • Secure channels between deployments (planned): carrying signals between separate libsig deployments over TCP, MQTT or ZMQ.
  • Cloud instances subscribing to device data (planned): a cloud deployment that receives and processes the signals a device produces.
